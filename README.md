# 频谱工作台（通信工程教学 · 离线简化模型）

用于比较一组载波频率配置的教学工具：录入少量载波、保护间隔与**按日重复的激活时段**
后，绘制频段占用与发射谱，检查 **频带重叠、保护带不足、掩模尾部越界**，在**线性域 (W)**
汇总功率后以 dBm 显示；极化复用由输入规则决定（禁止 / 允许 / 隔离度未知待评估）；
并可用 **OR-Tools CP-SAT** 为载波寻找一组满足间隔的频率位置。

所有冲突检查、频段图、掩模图与规划都只针对**同一时刻实际处于激活状态**的载波：
频率相同但激活时段不重叠的两个载波不会互相干扰，也不会被强行排开。

> ⚠️ 纯离线简化模型：**不连接无线电设备，不生成任何发射指令**。掩模与发射谱均为教学
> 用平顶 + 折线衰减的简化数值，不对应任何标准或真实设备指标。

## 快速开始

需要本机 PostgreSQL（或修改 `DATABASE_URL`）。提供一个 conda 方式安装的便捷脚本：

```bash
# 1) Python 依赖
pip install -r backend/requirements.txt

# 2) 前端依赖
cd frontend && npm install && cd ..

# 3) 初始化数据库并写入示例掩模 + 教学演示场景
python -m app.seed          # 工作目录为 backend/，或设置 PYTHONPATH

# 4) 启动
( cd backend && uvicorn app.main:app --reload --port 8000 )
( cd frontend && npm run dev )        # http://localhost:5173 ，/api 代理到 8000
```

环境变量：`DATABASE_URL`（默认 `postgresql+psycopg2://postgres@127.0.0.1:5432/spectrum`）、
`CORS_ORIGINS`。

## 计算模型要点

### 1. 激活时段与时间口径

每个载波携带 0..n 个**每日重复的激活区间**，按当地墙钟 `"HH:MM"` 录入并**显式携带
UTC 偏移**（`tz_offset_minutes`，如北京时间 UTC+8 = 480）：

- `end <= start` 表示**跨午夜**：如 `22:00–02:00` = 当日 22:00 起、次日 02:00 止。
- 区间为半开 `[start, end)`：同一载波自己的区间**不得重叠**，但允许**相接**
  （一个 12:00 结束、另一个 12:00 开始不算重叠）；时长 1..1439 分钟，不接受零长/24h。
- **区间列表为空 ⇔ 始终激活**。旧场景（无时间字段）启动时轻量迁移回填 `[]`，
  默认始终激活，历史分析结论完全不变。
- 物理时间比较在 **UTC 圆周（0..1440 分钟）**上进行：先按偏移把每个区间换算成
  UTC 弧，再求交集。因此同墙钟写法、不同偏移而物理时段错开的载波不会被判同时激活；
  相接（一端的结束恰为另一端的开始）不算同时激活。

分析/规划支持两种口径：

- **全天配对**（默认，`at_time` 缺省）：只对一天内存在正长度共同激活时段的载波对做
  几何/保护带/掩模检查；时间互不交叠的同频载波可安全同频（planner 中为
  `time-disjoint reuse`，不加任何频率约束）。
- **考察时刻**（`at_time = {local_time, tz_offset_minutes}`）：只统计该时刻实际激活
  的载波，频段图/谱图把未激活载波淡化（灰虚线/点线），功率汇总也只含激活载波。

时段重合时一切沿用既有口径：同极化按禁止、`forbidden/unknown` 报重叠/待评估、
保护带净距检查、双向掩模泄漏分别计算。每条 finding 附带 `time_scope.shared_utc`
（共同激活的 UTC 时段），并透传两载波各自的本地区间与跨午夜标记。

### 2. 冲突检查（`POST /api/analyze`，结果含 bands / spectrum / findings / power_summary / time_report）

- **频带重叠 overlap**：两频带边缘净距 `gap = max(low) − min(high) ≤ 0`，报重叠量。
- **保护带不足 guard_shortfall**：`0 < gap < guard_required_mhz`，报净距与缺口。
- **掩模尾部越界 mask_tail（有方向）**：发射机掩模谱落入受害载波频带的功率
  `P = ∫_victim 10^(PSD_dbm/10)·1mW df`（PSD 在线性 W/Hz 域积分），超过限值即报；
  因功率/掩模不同，A→B 与 B→A 分别计算、分别定位。
  以上三类仅在载波对同时激活时产生。
- **极化复用规则**（针对异极化对）：
  - `forbidden` 禁止：重叠即冲突；
  - `allowed` 允许（已知隔离度足够）：可同频，不报几何/泄漏冲突；
  - `unknown` 待评估：重叠只提示“隔离度未知，复用待评估”，不下违规定性；
  - 同极化对无极化隔离，始终按禁止处理。

### 3. 功率汇总

dB 是对数尺度，**不能直接相加**。先换算
`P_W = Σ 1mW · 10^(p_i/10)`，再 `P_dBm = 10 log10(P_W/1mW)`。
响应里同时给出错误的“dBm 直接求和”数值供课堂对比（例如多个载波 275 dBm vs 正确 36.14 dBm）。
考察时刻口径下只汇总当时激活的载波；该时刻无载波激活时总功率为 `null`。

### 4. OR-Tools 规划（`POST /api/plan`）

CP-SAT 在 1 kHz 网格上为每个载波选中心频率，约束：

- 落在给定可用频段内；
- 需要隔离的载波对（同极化 / 禁止 / 待评估）**且一天内存在共同激活时段**，通过布尔
  析取排序，满足 `中心距 ≥ 半宽_i + 半宽_j + 要求边缘净距`；
- 允许复用的极化对、以及**时间互不交叠的载波对**不加约束（可同址/同频）；
- 考察时刻口径下只规划当时激活的载波，其余列入 `inactive_carriers`；
- `guard_only`：统一用保护间隔；`mask_aware`：对每对同时激活载波按**双向**掩模泄漏
  都不越限反算所需净距（含 0.5 dB 规划裕量，保证返回方案在分析口径下必然达标）；
- 目标：最小化相对录入位置的总偏移。无解时返回 `INFEASIBLE` 与放宽建议。
  返回中带 `post_check`（对方案连同原时间窗口重新跑一遍完整分析）。

### 5. 已保存规划：绑定场景修订与时间窗口

`POST /api/scenarios/{id}/plans` 保存规划时记录：场景 `revision`（每次实质内容编辑
+1，改名/改描述不前进）与场景全部规划相关内容（频段、规则、载波频率/功率/极化/掩模，
以及每个时间窗口在 **UTC 圆周上的实际激活弧**）的 SHA256 `fingerprint`。

- 读取（`GET /api/plans/{id}`、场景下的列表）时与当前场景动态比对：指纹与修订都
  一致 => `executable`；否则 => `expired` 并给出原因。记录本身作为历史档案保留，
  不删除、不改写。
- `POST /api/plans/{id}/reuse`：过期方案一律 **409 拒绝复用**；可执行方案才返回结果。
  编辑时间窗口使方案失效后，界面会标“已过期”，必须基于当前场景重新求解；新方案的
  `post_check` 计数为零冲突/零警告。
- 指纹基于 UTC 弧而非录入文本：只把同一物理时段改写成另一时区的本地写法，
  方案仍可执行；真正改变“同一时刻谁在发射”的编辑才会使其过期。
- 状态在重启后保持一致（存的是修订号与指纹，过期与否读取时计算）。

## 教学演示场景（种子数据）

**教学演示场景**（12 个载波，无时间数据 → 始终激活，历史结论不变；带宽均 4 MHz）：

| 载波对 | 现象 |
|---|---|
| C1(30 dBm,loose) / C2(20 dBm,loose)，净距 0.5 MHz | 保护带不足 + 双向尾部越界，泄漏 15.4 vs 5.3 dBm（功率不同导致方向不对称） |
| C4(30,strict) / C5(25,loose)，净距 0.5 MHz | 保护带不足；仅弱载波 loose 尾部越界（强→弱 −8.6 dBm 达标边界，弱→强 10.3 dBm 越界） |
| C7(30,loose) / C8(20,strict)，净距 2 MHz | 保护带虽够，强载波拖尾仍越界 2.0 dBm；反向 −47.5 dBm 达标 |
| C9 / C10，重叠 0.5 MHz | 同极化频带重叠 |
| C1(H) / C6(V) 同频 | 规则 unknown → “复用待评估” |
| C11(RHCP) / C12(V) 同频 | 规则 allowed → 无冲突 |

**时段干扰演示场景**（4 个载波，全部 UTC+8，演示同一批载波在不同时间段的干扰）：

| 载波 | 频率/掩模 | 激活时段 | 说明 |
|---|---|---|---|
| T1 | 120 MHz，30 dBm | 08:00–18:00 | 白班 |
| T2 | 120 MHz，20 dBm | 18:00–次日08:00（跨午夜） | 夜班；与 T1 同频但时间不重叠 → 全天配对无冲突 |
| T3 | 120 MHz，20 dBm | 22:00–次日02:00（跨午夜） | 与 T2 在 22:00–02:00 同时激活且同频同极化 → 重叠冲突 |
| T4 | 134.5 MHz，25 dBm，loose | 12:00–14:00 | 与 T1 同时激活、净距 0.5 MHz → 保护带不足 + 单向尾部越界 |

```bash
# 纯函数 + 规划 + API（API 测试用内存 SQLite，无需外部服务）

```

56 个测试覆盖：dBm/W 换算、三类冲突对定位、泄漏方向性、三种极化规则、
两种规划模式的可行性与规划后零越界、场景 CRUD，以及时间维度：

- 区间解析/跨午夜/UTC 圆周换算、半开相接边界、自重叠拒绝、不同 UTC 偏移的物理交集；
- **验收 1**：两条同频载波在不重叠时段不产生任何冲突；
- **验收 2**：把一段延长到重叠后，同时出现正确的保护带不足与方向性双向泄漏结论；
- **验收 3**：保存规划 → 编辑时间使其失效 → 标记过期、复用返回 409 → 重新规划
  post-check 零冲突；改名/纯时区改写不误伤；
- **验收 4**：旧结构库启动迁移后默认始终激活、历史分析不变；跨午夜编辑与时刻口径；
  文件库重启后过期状态与历史结果保持一致。
